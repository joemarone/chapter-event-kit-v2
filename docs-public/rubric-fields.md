# Field Rubrics — Everything Except Mastery

This is how reviewers grade the rest of the Spark submission. The builder shows each section inline as you fill in the corresponding field, so you can self-check before submitting.

Mastery has its own doc — [rubric-mastery.md](rubric-mastery.md) — because it's the field that gets sent back most often. This doc covers the other six.

> Refresher: every field on every Spark is graded against [anatomy.md](anatomy.md). If a rule here ever conflicts with the anatomy doc, the anatomy doc wins.

---

## Name

A passing name is short, concrete, and uniquely googleable.

| Test | What passes | What bounces |
|---|---|---|
| **Length** | 1–4 words | 5+ words; anything with a tagline or colon |
| **Concrete** | Names a thing or names a vibe — pick one | Generic categories ("Science Fun", "Math Time") |
| **Unique** | Googling the phrase doesn't return 50 unrelated activities | Phrases that already mean something else online |
| **Clean** | No "Spark" in the name; no version numbers; no exclamation points | "Knot Tying Spark", "Cube Club v2", "Juggling!" |

**Reviewer call:** all four → approve. One miss → request changes with the specific test cited.

## One-liner

The single sentence that runs under the name in the kit, the post, the calendar invite. It earns its space if it does three things.

| Test | What passes | What bounces |
|---|---|---|
| **Verb-led** | Starts with or leads on what the kid *does* | Starts with "A fun activity where…" or "Kids will…" |
| **Specific outcome** | Names the actual skill, threshold, or thing produced | Vague ("learn many skills", "build confidence") |
| **Under 25 words** | Reads in one breath | Two sentences pretending to be one |

**Examples:**
- ✓ *"Solve a 3×3 Rubik's cube from any starting position using a memorable seven-step method."*
- ✓ *"Recite all 50 U.S. states from a blank map in under 90 seconds."*
- ✗ *"A fun and engaging activity where kids learn valuable skills and have a great time together."* — fails all three.
- ✗ *"This Spark teaches kids about juggling."* — no verb leading on the kid, no threshold, no specifics.

**Reviewer call:** all three → approve. One miss → request changes.

## How the kids participate

One paragraph (3–6 sentences) describing the *lived experience* of the Spark. Not the lesson plan. Not the learning objectives.

| Test | What passes | What bounces |
|---|---|---|
| **Physical reality** | A reader can picture bodies, hands, voices in the room | Abstract verbs ("engage", "explore", "interact") |
| **Specific moments** | Names what happens when, including the moment the trick clicks | Reads like a brochure — all benefit, no scene |
| **Right length** | 3–6 sentences | One sentence (too thin) or a full essay (too much) |
| **Answers "what are the kids actually doing?"** | A parent could walk in mid-Spark and instantly know what's going on | Reader still has questions about what the kids physically do |

**Pattern that usually works:** opening scene → what they try first → where they get stuck → the unlock → what the room looks like at the end.

**Reviewer call:** all four → approve. One miss → request changes with a specific rewrite suggestion.

## Materials

Two lists: **Parents bring** and **Facilitator provides**. Graded together.

| Test | What passes | What bounces |
|---|---|---|
| **Concrete** | Every item is shoppable as written ("Marbles", "Felt squares (assorted colors)") | Vague ("supplies", "art stuff", "small objects") |
| **One per line** | Clean list, no run-on items | "A bunch of marbles, tape, string, and other things you might need" |
| **Right length** | Facilitator side ≤ ~5 items for a Spark | More than 5 facilitator items (it's not a Spark anymore) |
| **Honest split** | What each *family* brings vs what the *host* supplies — not muddled | Same item appears on both sides; or "everyone brings everything" |
| **"Nothing to bring" allowed on parent side** | Empty parent list is fine and rendered as "Nothing to bring" | n/a |

**Reviewer call:** all four passing tests → approve. One miss → request changes. If the list is too long, the right fix is usually to simplify the Spark, not to trim the list.

## Cost

| Test | What passes | What bounces |
|---|---|---|
| **One of three formats** | "Free", a flat number ("$5 per attendee"), or a justified range ("$5–$15 because…") | Hand-waves ("a few bucks", "depends") |
| **Under $15/kid** OR **justified** | Free, $X up to $15, or any number with a clear *why* | $20+ with no explanation |
| **Matches materials** | If the materials list is short and cheap, the cost reflects that | "$30 per attendee" with three items on the facilitator list |

**Reviewer call:** all three → approve. Cost mismatches almost always trace back to materials — fix the underlying issue, not the cost number.

## Difficulty pick (Hard / Challenging / Impossible)

The submitter picks one. The reviewer agrees or pushes back. See [anatomy.md](anatomy.md#hard--challenging--impossible) for the definitions.

| Test | What passes | What bounces |
|---|---|---|
| **Belongs in the library at all** | The Spark clears the "what does not qualify" bar — no party tricks, no googleable five-minute bits | Spoon-on-nose, basic knots, simple card tricks, gag activities, outcome-less crafts |
| **Tier matches the mastery threshold** | A 9-year-old's reaction to the goal aligns with the picked tier — "I can't" → Impossible, "I'll try" → Challenging, "I'll need to learn this" → Hard | Picked Impossible to sound bigger; picked Hard because it felt safer |
| **Unlock is visible (Impossible only)** | Submission credibly explains *how* the impossible becomes possible inside the time box | Picked Impossible with no story for how a kid actually gets there |

**Reviewer call:** all applicable tests → approve the tier. Tier mismatch → suggest the right tier and request changes. Failure of the *first* test (doesn't belong at all) → reject the whole submission, not just the tier — the Spark itself isn't ready for the library.

## Reviewer summary card

For convenience, the review screen shows one row per field with its result:

| Field | Tests | Status |
|---|---|---|
| Name | 4 | ✓ / ✗ / partial |
| One-liner | 3 | ✓ / ✗ / partial |
| Participation | 4 | ✓ / ✗ / partial |
| Materials | 4 | ✓ / ✗ / partial |
| Cost | 3 | ✓ / ✗ / partial |
| Mastery (separate doc) | 5 | ✓ / ✗ / partial |
| Difficulty | 2–3 | ✓ / ✗ / partial |

**Overall decision:**
- All fields ✓ → approve, generate kit, move to placement.
- Any field ✗ on the "doesn't belong in the library" test → reject.
- Any other partial → request changes with specific notes; submitter revises and resubmits.
